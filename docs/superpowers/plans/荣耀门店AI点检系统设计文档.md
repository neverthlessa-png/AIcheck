## 一、项目概述

### 1.1 项目背景

本项目是一个基于大模型 API 的门店巡检验证系统，用于荣耀授权体验店的视频点检工作。系统通过 AI 分析门店督导上传的照片，自动判断是否符合点检规范要求，减少人工审核工作量。

### 1.2 目标用户

- **主要用户**: 门店督导（点检人员）
- **使用场景**: 门店巡检、物料陈列合规检查

### 1.3 核心价值

| 项目 | 说明 |
|------|------|
| **自动化检测** | 大模型自动分析照片，判断合规性 |
| **规范驱动** | 点检规范可配置，灵活适应版本变化 |
| **多模型支持** | 支持 OpenAI、Claude、国内模型切换 |
| **人工复核** | 疑似问题人工确认，确保准确性 |

## 三、核心模块设计

### 3.1 插件系统

#### 3.1.1 设计目标

- 支持 LLM、本地模型、规则引擎三类检测器
- 统一接口，可灵活扩展
- 配置驱动，动态加载

#### 3.1.2 插件分类

| 类型 | 用途 | 示例 |
|------|------|------|
| **LLM 插件** | 复杂场景理解、合规判断 | GPT-4V 分析物料陈列 |
| **本地插件** | 图片质量、重复检测 | 模糊检测、相似图片识别 |
| **规则插件** | 简单规则校验 | 时间校验、文件格式校验 |

#### 3.1.3 插件调度策略

```
检测结果请求
      │
      ▼
┌─────────────────┐
│ 查找专属插件     │  (question_code 匹配)
└────────┬────────┘
         │
    无专属插件
         │
         ▼
┌─────────────────┐
│ 按优先级选择     │  规则 > 本地 > LLM
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 执行检测         │
└────────┬────────┘
         │
         ▼
    返回结果
```

### 3.2 任务编排引擎

#### 3.2.1 核心职责

1. **任务解析**: 将输入数据解析为点检任务
2. **规范匹配**: 根据问题编号匹配点检规范
3. **检测调度**: 调用合适的检测器插件
4. **结果聚合**: 汇总所有检测结果，计算得分
5. **报告生成**: 生成点检报告

#### 3.2.2 处理流程

```
┌─────────────────────────────────────────────────────────────┐
│                        输入数据                              │

                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      1. 任务创建                             │

└─────────────────────────────┬───────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      2. 图片预处理                           │
│  • 验证图片格式                                               │

│  • 计算图片哈希（去重）                                        │
│  • 存储图片信息                                               │
└─────────────────────────────┬───────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐

│  • 调度检测器插件                                             │
│  • 并行/串行执行（可配置）                                      │
│  • 收集检测结果                                               │
│  • 错误处理与重试                                             │
└─────────────────────────────┬───────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      5. 结果聚合                             │
│  • 汇总各问题检测结果                                          │

### 3.3 数据输入模块

#### 3.3.1 输入方式

| 方式 | 说明 | 优先级 |
|------|------|--------|
| **手动导入** | 用户选择图片文件夹，手动关联问题编号 | MVP 必需 |
| **问卷对接** | 通过 API 从问卷系统获取问题和照片 | 后续迭代 |

#### 3.3.2 数据结构

```
输入数据:
├── 门店信息
│   ├── 门店编号
│   ├── 门店名称
│   └── 区域
├── 图片列表
│   ├── 图片文件路径
│   ├── 对应问题编号 (question_code)
│   └── 可选: 拍摄时间
└── 可选: 问卷来源

    └── 提交时间

    class: OpenAIPlugin

      model: "gpt-4o"

  - name: anthropic_claude
    enabled: false
    type: llm
    module: ai_check.plugins.llm.claude_plugin
    class: ClaudePlugin
    config:
      api_key: "${ANTHROPIC_API_KEY}"
      model: "claude-sonnet-4-6-20250514"

  # 本地插件
  - name: image_quality
    enabled: true
    type: local
    module: ai_check.plugins.local.quality_plugin
    class: ImageQualityPlugin
    config:
      blur_threshold: 100

  - name: duplicate_detector

    type: local
    module: ai_check.plugins.local.duplicate_plugin

      hamming_threshold: 5

## 十、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| **API 调用成本** | 中 | 本地插件优先，减少 LLM 调用；设置调用限额 |
| **API 响应慢** | 中 | 异步处理，进度提示；支持中断恢复 |
| **检测结果不准** | 高 | 人工复核机制；持续优化提示词 |
| **规范版本变化** | 中 | 规范配置化，支持多版本 |
| **图片隐私** | 低 | 本地存储，不上传云端 |
